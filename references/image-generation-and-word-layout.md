# 场景图片生成与 Word 图册规范

当用户要求“分析后直接生成图片”“按场景排序出图”或“输出场景资料汇总”时，使用本规范。最终交付必须是一个可直接打包分享的项目文件夹：Word 图册负责完整阅读，`images/` 子文件夹保留全部中文命名的原始场景图。除非用户明确要求，不再制作 Markdown 图册。

## 1. 固定交付结构

```text
《项目名》_场景资料汇总/
├─ 《项目名》场景资料汇总.docx
└─ images/
   ├─ S01_主场景－次场景_日.png
   ├─ S01_主场景－次场景_日—反.png
   ├─ S01_主场景－次场景_夜.png
   └─ S01_主场景－次场景_夜—反.png
```

- Word 文件与 `images/` 必须位于同一项目文件夹内。
- 图片必须真正嵌入 DOCX，不得依赖外部链接；移动或压缩整个文件夹后，Word 仍应能正常显示全部图片。
- `images/` 仍是独立可用的美术资产目录，不得因图片已经嵌入 Word 而省略。
- 不生成同内容的 `.md` 文件，除非用户单独提出。

## 2. 场景资产与空间身份

- 默认以合并后的“主场景 + 次场景”为一个场景资产。门口、院内、正厅、卧室、走廊等视觉独立的次场景必须分别出图。
- 同一场景重复出现且建筑、陈设和时代状态一致时，只生成一组图片，并汇总全部场次与集数。
- 日、夜、清晨、黄昏、闪回、梦境、预见等具有实质视觉差异的状态分别生成完整版本。
- 只在对白中提及、观众并未看见的地点不出图；动作段落中实际被视觉化的隐含场景必须纳入。
- 每个时间或叙事版本由一张主图和一张同空间反打图组成，二者是不可拆分的交付单元。
- 先为实际环境分配 `SPACE-ID`，再为独立分区分配 `ZONE-ID`。名称不同但属于同一物理空间的场景，必须共享同一空间母版、拓扑、固定锚点和规范反向环境。
- “次场景分别出图”只表示需要不同视图，不表示可以重新设计相连空间。

## 3. 编号、中文命名与排序

- 按全剧首次出现顺序编号：`S01`、`S02`、`S03`……编号一经确认保持稳定。
- 同一场景的版本紧邻排列，建议顺序：清晨、日、黄昏、夜、其他叙事状态。
- 文件名必须包含中文场景名称。仅替换 Windows 非法字符 `\ / : * ? " < > |`，不把中文转写为英文或拼音。
- 主图：`S01_主场景－次场景_日.png`。
- 反打：`S01_主场景－次场景_日—反.png`。
- 必须使用准确后缀 `—反`，不得写成 `-反`、`_反` 或 `reverse`。
- 临时重试文件可以加入 `v2`，但最终项目只保留被接受、且符合正式命名规则的版本。

## 4. 主图生成规则

- 每个场景资产或时间版本单独生成，默认是无人物环境概念图，21:9 超宽银幕构图；目标尺寸 2560×1088。
- 重点展示整个场景的设计、空间层级、主要表演区与总体氛围。不以前景化的动线、动作机制、证物链或关键道具关系作为主体。
- 不出现人物、演员、人群、肢体、字幕、乱码标牌、水印、分镜格或版式文字。
- 提示词应包含地域与时代、主/次场景、建筑与材质、全景视角、主要表演区、空间层级、时段、物理可信主光、补光策略、对比度、色温、空气介质、镜头与写实质感。
- 日夜版本必须保持建筑、固定陈设、材质和核心表演区一致，但分别构建完整光源体系；夜景不是日景简单调暗或变蓝。
- 地面反光保持克制、物理可信，除非剧本明确要求积水、抛光材料或强反射效果。

## 5. 反打图与跨镜头一致性

1. 主图通过初检后，立刻以该图为主要视觉参考生成反打；这一对完成前不得开始下一资产。
2. 生成前先推断空间闭环：可见门窗、楼梯、走廊口、柱、固定柜体、主要家具、摄影机背后墙面、入户门和内部通道。
3. 反打是机位变化，不是镜像、翻转、裁切或重新设计。摄影机移动到主要表演区另一侧，保持真实可站机位。
4. 建筑尺度、门窗数量与位置、固定陈设、家具位置、材质、时段、天气和光源逻辑必须连续。
5. 如果主图没有可信入户门，反打应在未见且平面允许的墙面补全入口，并通往合理的玄关、走廊、楼梯厅、院落或室外；不得与已知窗、墙、家具冲突。
6. 入口的尺度、门型、开启方式、门套、五金、门槛与磨损必须符合时代、地域、阶层和建筑类型，不得跨场景机械复用。
7. 反打必须保留主图中 1–3 个可识别连续性锚点，并从相反方向看到它们。
8. 同一 `SPACE-ID` 下，即使场景名、分区名或镜头用途不同，也必须引用空间母版及既有规范反打。面向相近方向的镜头应回到同一个反向环境；透视和遮挡可以变化，门窗、柱网、固定家具和外景不可漂移。
9. 日、夜及其他状态分别生成自己的反打。夜反打以夜主图为参考，不能由日反打调暗替代。
10. 新视图若揭示此前未见分区，先把它加入空间拓扑并验证与全部既有图兼容，再生成。

反打提示词必须明确包含：

> 以已接受的主场景图和该 SPACE-ID 的空间母版为视觉参考，生成同一空间、同一时段、同一陈设状态的真实反打机位。严格保持已建立的建筑结构、门窗、材质、固定家具、陈设位置和尺度；摄影机移动到主要表演区另一侧，不做水平镜像，不重新设计已知空间。若原视角没有功能可信的入口，只在未展示且平面关系允许的墙面补全符合建筑类型、时代、地域、阶层和剧情功能的入口。保留 1–3 个连续性锚点并从相反方向看见；维持相同焦段家族、光源逻辑、色温、空气介质和写实电影质感。无人物、无文字、无水印。

## 6. 图片复查与重试

每对图片至少检查：

1. 主图是否准确呈现场景、时代、地域、全景和主要表演区；
2. 反打是否为真实对侧机位，而非镜像、裁切或另一房间；
3. 门窗、楼梯、柱、墙面分隔、家具数量及位置是否互相解释；
4. 室内入口是否功能可信，并与已知平面兼容；
5. 是否保留 1–3 个连续性锚点；
6. 材质、色彩、陈设、时段、天气、光向、色温和空气介质是否连续；
7. 是否出现人物、文字、水印、拼贴边框或明显透视、比例、结构错误；
8. 是否与同一 `SPACE-ID` 下全部其他视图一致，而不只是单独这一对看似合理。

发现漂移时，继续以已接受主图和空间母版为参考，用具体修正提示重试。不能用虚假路径或占位图冒充成功结果。

## 7. Word 文档结构

Word 文件建议命名为 `《项目名》场景资料汇总.docx`，并依次包含：

1. 封面：项目名、版本、剧本覆盖范围、场景资产数、时间版本数、主图数、反打数、完成/失败数。
2. 影视美术场景阐述：整体美术概念、地域时代、色彩叙事、材质、建筑、镜头构图及布光体系。
3. 剧本场景清单：严格使用“主场景、次场景、场次 / 集数、日夜、核心剧情场景备注”五列。
4. 场景索引：按 `S##` 顺序列出中文场景名及页码；能生成自动目录时优先使用标题样式与目录域。
5. 场景图册：每个 `S##` 独立成节，同一场景的时间版本紧邻排列。

每个场景章节固定顺序：

1. `标题 1`：`S01 · 主场景－次场景`。
2. 紧凑信息表：大区、优先级、场次 / 集数、日夜、生成状态。
3. 场景简介：场景身份、总体空间、主要表演区、剧情功能与状态变化。
4. 若有多时段，以 `标题 2` 标记“日景版本”“夜景版本”等。
5. 主图题注及主图。
6. 反打题注及反打——必须紧接主图，不得在两图之间插入说明、提示词或其他图片。
7. 该版本的布光 / 光感说明。
8. 主图生成提示词与反打生成提示词，使用浅灰底单列表格或专用“提示词”样式，9 磅左右，避免挤压图片。

## 8. Word 版式

- 页面默认 A4 纵向，上下左右页边距约 1.5–1.8 厘米；若项目模板另有要求可调整。
- 正文使用常见中文字体，正文 10.5–11 磅，标题层级清楚；不要依赖仅在单台电脑安装的特殊字体。
- 21:9 图片按页面可用宽度等比缩放，不拉伸、不裁掉主体、不横向压扁。
- 优先让一组主图和反打同页连续展示；若空间不足，在主图前主动分页，使一对图片落在同一页。仍无法同页时，反打必须成为紧随主图的下一页首项。
- 图片使用嵌入式“与文字在一行”布局，防止浮动错位。主图与反打宽度保持一致。
- 图片题注简短统一，例如 `图 S01-A  主场景－次场景（日）`、`图 S01-B  主场景－次场景（日）—反`。
- 表格必须设置重复标题行、合理列宽和不跨页拆分关键行；长场次信息允许自动换行。
- 章节末使用分页控制，避免标题孤立在页底。不得出现大面积意外空白页、截断图片、越界表格或不可读的小字。

## 9. DOCX 制作与渲染验证

- 使用文档工具或 `python-docx` 生成 Word；图片必须以二进制形式嵌入文档包。
- 生成后使用文档技能提供的 `render_docx.py` 渲染为逐页图片，并查看每一页。
- 逐页检查封面、场景表、目录、题注、图片比例、分页、提示词块和页码；发现溢出或错页后修改并重新渲染。
- 运行：`python scripts/validate_scene_word_atlas.py <DOCX路径> --images-dir <images目录>`。
- 校验通过与视觉渲染检查通过缺一不可。

## 10. 完成状态与最终检查

- 只有全部计划主图和反打真实存在并通过复查，封面才可写 `N/N 已完成`。
- 部分失败时写明 `已完成 X/N，待重试 Y`，并在对应章节标记失败项，不插入虚假占位图。
- 全部正式场景和合格隐含场景均已覆盖，并按首次出现排序。
- 每个独立次场景拥有自己的提示词和图片对；同空间分区仍满足统一拓扑。
- 日夜分别出图、分别写布光，并各自拥有反打图。
- 每张主图后紧邻一张反打；文件名使用准确的 `—反` 后缀。
- 图片文件名包含中文场景名；DOCX 内嵌图片数与 `images/` 最终图片数一致。
- 同一 `SPACE-ID` 的全部主图、反打、分区图和日夜版本能落入同一空间拓扑，规范反向环境一致。
- Word 每页已渲染检查，项目文件夹可整体压缩分享。
